# Document Types

Select the requested deliverable and read only its reference. Preserve the three modes and the writer's voice. Leave the type unset when unclear. A type alone does not authorize changing polite/plain style.

| Type | Reference | Usual mode |
|---|---|---|
| `pr` | [PR and Issue bodies](doc-types/pr.md) | `argument` |
| `spec` | [Specifications and designs](doc-types/spec.md) | `argument` |
| `incident` | [Incident reports](doc-types/incident.md) | `argument` |
| `minutes` | [Meeting minutes](doc-types/minutes.md) | `argument` |
| `article` | [Articles and personal writing](doc-types/article.md) | `argument / narrative` |
| `proposal` | [Proposals](doc-types/proposal.md) | `argument` |
| `slides` | [Slides](doc-types/slides.md) | `argument / narrative` |
| `mail` | [Mail and chat](doc-types/mail.md) | `mail` |
| `manual` | [Manuals and procedures](doc-types/manual.md) | `argument` |

Type exceptions affect form only; they never waive facts, conditions, uncertainty or the voice rules. Explicit requests and the selected voice take priority; apply type guidance within them. See [word preferences](word-preferences.md) for lexical settings.

The explainer subtype requires an explicit request; selecting article does not activate it.

Design reference: [yomiyasu v3.4.1 document types](https://github.com/nanaism/yomiyasu/tree/3979c750b5e1fe9892bd47bb354f0fb51d534ff2/skills/yomiyasu/references/doc-types) (MIT). These rules and categories are independently written for ja-humanizer.
