# 書き下ろしの評価

推敲の前後だけでなく、同じ材料から生成して比べる。モデル、適用する指示、材料、読者、長さ、文体見本を固定する。生成用の依頼には期待する判定を見せず、出力を保存してから評価する。生成結果を承認済みの文体見本にしない。

## 繰り返し使う課題

[実際の依頼文](evaluation/generation-203/prompt.txt)では、障害報告、手順書、スライド、メールを独立した4件として書かせる。再起動についての曖昧な記述は意図的に含めた。生成後に次を確認する。

| 課題 | 確認すること |
|---|---|
| 障害報告 | 更新後に値が戻ることを直接説明し、不確実性を残す。ログ不足、原因、保証を作らない。曖昧な再起動の記述は一方に決めず確認する。 |
| 手順書 | 番号付き3手順、管理者だけが承認できる条件、ボタンが無効になる条件を保つ。同じ丁寧な語尾を許容する。 |
| スライド | 短い見出しと箇条書き3項目、送信前の修正条件、未測定・未定の値を保つ。時間短縮の数値を作らない。 |
| メール | 挨拶、結び、送り手と相手を保ち、確認と修正箇所の連絡を頼む。金額、期限、添付資料を作らない。冗長さと追加した依頼も別に確認する。 |

別の試行では、本人が承認した見本を使い、見本と異なる題材で書かせる。物理的な故障、専門用語、引用、資料に基づく数値のない効果は、直さない例として確認する。状態が詳しく分からない故障の材料から、勝手に原因を狭めないことも試す。嫌な表現、追加した事実、欠けた条件、直しすぎ、手直しの負担を検出件数とは別に記録する。本人の好みと修正時間は本人による評価が必要になる。

## 2026-11-25 の試行記録

[記録ファイル](evaluation/generation-203/manifest.json)に、試した両版のファイルのハッシュと実行条件を残した。[旧版の出力](evaluation/generation-203/base.md)と[変更版の出力](evaluation/generation-203/candidate.md)は評価用の生成物であり、本人の文章や承認済みの見本ではない。両CLI実行は成功し、それぞれの版の検査を実行した。モデルはともに GPT-6.2 Sol、推論設定は medium。各版1回、1回に4課題を与え、文体見本と語彙設定は使わないよう指定した。変更版は作業途中の保存版である。その後の保護範囲の検査修正とスライドの文長説明の明確化は、今回の入力に保護範囲や文体目標がないため、生成を再実行していない。

保存した出力をエージェントが読み比べた範囲では、両版とも主要な事実、権限、形式を保ち、再起動の曖昧な記述を確認事項にした。対象とする曖昧な比喩は、今回の4件では両版とも新たに加えなかった。変更版の手順書では依頼の語尾がそろい、旧版では依頼と説明の語尾が混在した。どちらも理解できる。旧版のメールは修正後の文言の希望を尋ね、変更版はメールへの返信を求め、改まった感謝の表現を使った。これは観測できた違いであり、品質の改善を測定した結果ではない。

この小さな試行では、文章品質が明確に改善したとは結論づけられない。本人による採点と修正時間の測定は行っていない。文体見本なしの明示的な呼び出しなので、本人の文体の保持、自動的なスキル選択、繰り返し実行したときの安定性もこの試行の評価対象には含まれない。検査コードのテストは検出と種類別の除外を確かめるもので、文章品質の証明とは分ける。
