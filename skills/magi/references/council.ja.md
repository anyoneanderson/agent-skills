# 合議プロトコル — プロンプトと出力のテンプレート

ホストが賢者へ送る文と、ユーザーへ見せる文をここにまとめる。判断規則は
`SKILL.md`、文面はこのファイルが持つ。

プロンプトはユーザーの言語で書く。ユーザーが読める言語で理由が返ってくるように
するためである。英語版は [council.md](council.md) にある。

## 表記の約束

- `{{二重波括弧}}` はホストが埋める箇所を表す。プロンプトファイルに波括弧を
  残さない。
- 1回の送信につきプロンプトファイル1つを、実行ディレクトリの下へ保存する:
  `round1/prompt.md`、`debate1/prompt-<賢者名>.md`、
  `deliberation1/prompt-<賢者名>.md`。round1 は全賢者へ同じファイルを送り、討論と
  審議は賢者ごとに別のファイルを送る。
- どのテンプレートも回答形式の指示で終える。プロンプトの途中に置くと賢者が
  読み飛ばしやすいので、最後に置く。
- どのプロンプトでも他の賢者の名前・提供元・モデル名を書かない。round1 では
  他の賢者が存在すること自体を伏せる。討論と審議では他の賢者を **Sage A** /
  **Sage B** としてのみ示す。

## 1. decision / round1 — 初回の質問

3体へ同一の文を送る。独立性を確保するラウンドなので、他の賢者にも尋ねている
ことを知らせない。

```text
あなたは専門家として助言する立場です。以下の問いに、あなた自身の判断で答えて
ください。

## 問い

{{QUESTION}}

## 検討中の選択肢

{{OPTIONS — 1行1件。問いが自由記述なら、この節ごと削除する}}

## 前提

{{CONTEXT — 制約、実行環境、すでに試したこと、この判断が影響する範囲。助言に
必要な範囲だけ書く。ここに書いた内容はすべて外部サービスへ送信される}}

## やること

1. 立場を1つ選ぶ。上の選択肢で網羅されている場合はその中から選び、そうでなけ
   れば別の立場を提案してよい。
2. 理由を5文以内で書く。考慮点を並べるのではなく、判断を決めたトレードオフを
   名指しする。
3. 確信度を high / medium / low で示す。自分が確信を持てない事実に判断がどれ
   だけ依存しているかを基準にする。

確認の質問は返さないこと。与えられた情報で判断し、置いた仮定は理由の中に書く。

## 回答形式

JSON オブジェクト1つだけを返す。前後に文章を付けず、コードフェンスも付けない。

{"position": "<あなたの立場を1行で>", "rationale": "<理由。5文以内>", "confidence": "high|medium|low"}
```

## 2. decision / 討論 — keep / switch / compromise

3体の立場がすべて異なるときだけ、**賢者ごとに1通**送る。受け取る賢者には自分
の前回回答と、他の2体を匿名化した回答を見せる。

```text
あなたは専門家として、いちど出した判断を再検討する立場です。同じ問いに他の
2名の助言者が独立に答え、それぞれ別の結論を出しました。その回答を匿名で下に
示します。誰の回答かは意図的に伏せてあります。主張の出どころではなく、主張の
中身を評価してください。

## 問い

{{QUESTION}}

## あなたの前回回答

立場: {{OWN_POSITION}}
理由: {{OWN_RATIONALE}}
確信度: {{OWN_CONFIDENCE}}

## Sage A

立場: {{SAGE_A_POSITION}}
理由: {{SAGE_A_RATIONALE}}
確信度: {{SAGE_A_CONFIDENCE}}

## Sage B

立場: {{SAGE_B_POSITION}}
理由: {{SAGE_B_RATIONALE}}
確信度: {{SAGE_B_CONFIDENCE}}

## やること

次の3つから1つだけ選ぶ。

- keep — 自説を維持する。A または B の主張のどこに納得できないかを書く。
- switch — A または B の立場へ乗り換える。何に説得されたかを書き、乗り換えた
  先の立場を "position" に入れる。
- compromise — 対立を解消する折衷案を出す。新しい立場を "position" に入れ、
  A または B のどの懸念に応えたかを書く。

良い反論で考えを変えるのは正しい振る舞いであり、まだ正しいと考える立場を維持
するのも正しい。対立を終わらせるためだけに乗り換えないこと。

## 回答形式

JSON オブジェクト1つだけを返す。前後に文章を付けず、コードフェンスも付けない。

{"action": "keep|switch|compromise", "position": "<このラウンド後のあなたの立場を1行で>", "rationale": "<理由。5文以内>", "confidence": "high|medium|low"}
```

2ラウンド目（`debate2`）では、他の2体の**討論後**の立場を入れて同じテンプレー
トを使い、「あなたの前回回答」には `debate1` の回答を入れる。

## 3. research / round1 — 独立した調査

3体へ同一の文を送る。decision の round1 と同じく、他の賢者にも尋ねている
ことを知らせない。

```text
あなたは調査を担当します。以下の主題を調べ、見つけたことを報告してください。

## 主題

{{QUESTION}}

## 調査範囲

{{SCOPE — 対象とする期間・バージョン・地域・情報源、および範囲外とするもの。
主題だけで自明ならこの節ごと削除する}}

## やること

1. 発見は1件ずつ分けて報告する。3件から8件が扱いやすい範囲で、主題が狭ければ
   少なくてよい。
2. 発見ごとに、主張を1文で書き、根拠と、それをどこから得たかを書く。
3. 自分で確認した内容と、記憶から述べている内容を区別する。学習データに基づく
   主張で、その後変わっている可能性があるなら、根拠の欄にそう書く。
4. 問いの前提を否定する発見があれば、それを報告する。返せるもののうち最も価値
   が高い。

根拠を示せない主張は、弱い形で報告するのではなく除外する。

## 回答形式

JSON オブジェクト1つだけを返す。前後に文章を付けず、コードフェンスも付けない。

{"findings": [{"claim": "<1文>", "evidence": "<何がそれを支えるか、どれだけ新しい情報か>", "source": "<URL / 文書名 / コマンド出力 / 「<時点>までの学習データ」>"}]}
```

### ディープリサーチ用の差し替え

ユーザーがディープリサーチを選んだときは、「主題」と「調査範囲」を残し、
「やること」と「回答形式」を次の内容へ差し替える。

```text
## やること

1. Web 検索を最低5回実行する。同じ言い換えを繰り返さず、主題の異なる側面を
   確認するクエリを使う。
2. 問いの前提、または調査で有力になった説明に反する証拠を探す検索を最低1回
   実行する。
3. 発見は1件ずつ報告する。HTTP または HTTPS の出典 URL がある発見だけを含め、
   URL を示せない発見は除外する。
4. 主張を1文で書き、出典が何を裏付けるかと、その情報がどれだけ新しいかを書く。
5. 実行した検索クエリをすべて監査用に返す。

提供元が用意する Deep Research 製品は呼び出さない。この賢者環境で利用できる
ツールを使って検索を実行する。

## 回答形式

JSON オブジェクト1つだけを返す。前後に文章を付けず、コードフェンスも付けない。

{"findings": [{"claim": "<1文>", "evidence": "<出典が何を支えるか、どれだけ新しい情報か>", "source": "<http:// または https:// の URL>"}], "search_queries": ["<検索1>", "<検索2>", "<検索3>", "<検索4>", "<検索5以降>"]}
```

## 4. research / 審議 — 単独発見の評価

**賢者ごとに1通**作り、`deliberation1/prompt-<賢者名>.md` へ書く。そこに載せる
のは、その賢者が報告しなかった単独発見だけである。全通を1回の並列起動で配布する。

全員へ同じ1通を送ってはいけない。2体がそれぞれ単独発見を出している場合、共有の
1通では、ある賢者に自分の主張を審議させる（それは審議ではない）か、審議が必要な
発見を落とすかのどちらかになる。宛先ごとに絞り込むことだけが、どの発見も「報告
しなかった賢者」によって評価される配り方である。

回覧は1回だけなので、ある賢者が評価すべき発見はその賢者のプロンプトにまとめる。
評価対象が無い賢者にはプロンプトファイルを作らず、`--sages` から外す。プロンプト
の無い賢者への送信はスクリプトが拒否する。

```text
あなたは、別の調査者が報告し、あなたは報告しなかった主張を評価します。それぞれ
について、統合レポートへ載せるべきかを判断してください。

## 主題

{{QUESTION}}

## 評価対象の主張

### {{FINDING_ID}}

主張: {{CLAIM}}
提示された根拠: {{EVIDENCE}}
提示された出典: {{SOURCE}}

{{単独発見1件につき1ブロック繰り返す}}

## やること

主張ごとに判定を1つ返す。

- agree — 正しく、根拠も足りていると考える。
- conditional — ある条件下、一部のバージョン、一部の地域でのみ成り立つ、または
  特定の点を確認できた場合にのみ成り立つ。その条件を書く。
- reject — 誤っている、または根拠が足りないと考える。そう考える理由を書く。

主張の中身を評価し、書き方で判断しない。もっともらしいという理由で agree に
せず、自分が報告しなかったという理由で reject にしない。

## 回答形式

JSON オブジェクト1つだけを返す。前後に文章を付けず、コードフェンスも付けない。

{"verdicts": [{"finding_id": "<上の ID>", "verdict": "agree|conditional|reject", "rationale": "<理由。3文以内。conditional のときは条件を書く>"}]}
```

既定はまとめ形式（`verdicts` 配列）である。どの判定がどの主張に対応するかは
`finding_id` が結びつけている。その賢者のプロンプトに載る発見がちょうど1件のとき
だけ、次の単一判定の形も同じ意味で使える。

```text
{"verdict": "agree|conditional|reject", "rationale": "<理由。3文以内>"}
```

## 5. `--schema-file` 用の JSON スキーマ

`schema_args` を持つ賢者（既定では CASPER）は、回答形式を依頼ではなくスキーマ
で拘束できる。該当するスキーマを実行ディレクトリへ書き、`--schema-file` で渡す。

decision / round1:

```json
{
  "type": "object",
  "properties": {
    "position": { "type": "string" },
    "rationale": { "type": "string" },
    "confidence": { "type": "string", "enum": ["high", "medium", "low"] }
  },
  "required": ["position", "rationale", "confidence"],
  "additionalProperties": false
}
```

decision / 討論（上に `action` を追加した形）:

```json
{
  "type": "object",
  "properties": {
    "action": { "type": "string", "enum": ["keep", "switch", "compromise"] },
    "position": { "type": "string" },
    "rationale": { "type": "string" },
    "confidence": { "type": "string", "enum": ["high", "medium", "low"] }
  },
  "required": ["action", "position", "rationale", "confidence"],
  "additionalProperties": false
}
```

research / round1:

```json
{
  "type": "object",
  "properties": {
    "findings": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "claim": { "type": "string" },
          "evidence": { "type": "string" },
          "source": { "type": "string" }
        },
        "required": ["claim", "evidence", "source"],
        "additionalProperties": false
      }
    }
  },
  "required": ["findings"],
  "additionalProperties": false
}
```

ディープリサーチ / round1:

```json
{
  "type": "object",
  "properties": {
    "findings": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "claim": { "type": "string" },
          "evidence": { "type": "string" },
          "source": { "type": "string", "pattern": "^https?://" }
        },
        "required": ["claim", "evidence", "source"],
        "additionalProperties": false
      }
    },
    "search_queries": {
      "type": "array",
      "minItems": 5,
      "items": { "type": "string" }
    }
  },
  "required": ["findings", "search_queries"],
  "additionalProperties": false
}
```

research / 審議:

```json
{
  "type": "object",
  "properties": {
    "verdicts": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "finding_id": { "type": "string" },
          "verdict": { "type": "string", "enum": ["agree", "conditional", "reject"] },
          "rationale": { "type": "string" }
        },
        "required": ["finding_id", "verdict", "rationale"],
        "additionalProperties": false
      }
    }
  },
  "required": ["verdicts"],
  "additionalProperties": false
}
```

## 6. 出力テンプレート — decision 可決

```markdown
## 合議結果: 可決 — {{立場}}（{{N}}対{{M}}）

| 賢者 | 立場 | 理由の要旨 | 確信度 | 討論後 |
|---|---|---|---|---|
| MELCHIOR (claude) | {{立場}} | {{要旨}} | high | 維持 |
| BALTHASAR (codex) | {{立場}} | {{要旨}} | medium | 乗り換え → {{立場}} |
| CASPER (grok) | {{立場}} | {{要旨}} | high | — |

**少数意見**: {{賢者名}} は {{立場}} を主張。{{理由}}（採決では敗れたが、この
理由があなたの状況にはなお当てはまる可能性があるため記録に残す）

**監査ログ**: {{OUT_DIR}} に送信した全プロンプトと受信した生の回答がある。
```

- 「討論後」列は、討論なしで round1 で可決したときも表から外さない。その場合は
  全セルを「討論なし」で埋める。`—` は、討論が行われたうえでその賢者に書くべき
  推移が無いときにだけ使う。列を削ると、読み手は「討論が行われなかった」のか
  「討論の結果がこの報告に載っていない」のかを区別できなくなる。
- 回答できなかった賢者も行を残す:
  `| CASPER (grok) | 回答なし（タイムアウト） | — | — | — |`。括弧内の理由は
  タイムアウト / エラー / 回答不正のいずれか。
- 少数意見は1文でも必ず書く。書かなければ、合議は手数の多い単一モデルと変わら
  なくなる。

## 7. 出力テンプレート — decision 不成立

```markdown
## 合議結果: 不成立 — あなたの判断へ差し戻し

{{実施ラウンド}}行ったが、2体以上が支持する立場は出なかった。判断はあなたに
委ねる。以下は合議で分かったことである。

| 賢者 | 最終立場 | 理由の要旨 | 確信度 | 立場の推移 |
|---|---|---|---|---|
| MELCHIOR (claude) | {{立場}} | {{要旨}} | high | {{推移}} |
| BALTHASAR (codex) | {{立場}} | {{要旨}} | medium | {{推移}} |
| CASPER (grok) | {{立場}} | {{要旨}} | low | {{推移}} |

### 何を争っているか

**{{争点}}**
- MELCHIOR: {{主張}}
- BALTHASAR: {{主張}}
- CASPER: {{主張}}

{{争点1つにつき1ブロック繰り返す}}

### 決着に必要なもの

{{各争点を解消する事実または計測。賢者自身が確信を持てないと述べた点から
拾い、ホスト自身の意見は入れない}}

**監査ログ**: {{OUT_DIR}} に送信した全プロンプトと受信した生の回答がある。
```

`{{実施ラウンド}}` には実際に行った討論のラウンド数を書き、「立場の推移」欄も
実施したラウンドの内容だけで書く。

| 合議の規模 | `{{実施ラウンド}}` | 推移の書き方の例 |
|---|---|---|
| 3体・`debate1` + `debate2` | `討論を2ラウンド` | `2ラウンド通じて維持`、`debate2 で折衷案`、`debate1 で乗り換え、その後復帰` |
| 2体・`debate1` のみ | `討論を1ラウンド` | `維持`、`乗り換え → {{立場}}`、`折衷案` |

2体運転の討論は1ラウンドまでなので、その報告に「2ラウンド」と書くと監査ログと
食い違う主張になる。2体運転の表は2行で、`debate2` は登場しない。

不成立のときは争点の整理が成果物である。最終立場を並べただけの不成立報告は、
ユーザーがすでに恐れていたこと以上を伝えていない。

## 8. 出力テンプレート — research 統合レポート

```markdown
## 合議調査: {{主題}}

{{1段落。合議で確からしいと判断できたことと、意見が割れた箇所}}

### 裏取り済み（{{N}}件）

| 発見 | 支持 | 根拠 |
|---|---|---|
| {{主張}} | 3体中3体 | {{根拠と、最も強い出典}} |
| {{主張}} | 3体中2体 | {{根拠}} — MELCHIOR は報告していない |

### 条件付き採択（{{N}}件）

| 発見 | 報告した賢者 | 審議結果 | 条件 |
|---|---|---|---|
| {{主張}} | CASPER | BALTHASAR: conditional、MELCHIOR: agree | {{条件}} |
| {{主張}} | MELCHIOR | BALTHASAR: agree、CASPER: reject | 意見が割れた: {{両者の主張}} |
| {{主張}} | BALTHASAR | MELCHIOR: conditional、CASPER: reject | {{条件}}と、棄却の理由: {{理由}} |

### 棄却（{{N}}件）

| 主張 | 報告した賢者 | 棄却理由 |
|---|---|---|
| {{主張}} | BALTHASAR | 2体とも reject: {{理由}} |

### 賢者別サマリー

| 賢者 | 発見数 | 重点 | 備考 |
|---|---|---|---|
| MELCHIOR (claude) | 5 | {{何を重視したか}} | — |
| BALTHASAR (codex) | 4 | {{何を重視したか}} | 1件が棄却 |
| CASPER (grok) | 0 | — | 回答なし（タイムアウト） |

**監査ログ**: {{OUT_DIR}} に送信した全プロンプトと受信した生の回答がある。
```

- 棄却した発見も表に残す。1体が信じ、他の2体が否定した主張は、単一モデルの
  回答なら見えないままだった情報である。
- ディープリサーチでは URL のない発見を未検証として棄却欄に載せる。監査記録には
  残すが、審議へ回さず、採択もしない。
- 主張は一致していても細部（日付・バージョン・数値）が食い違うときは、主張を
  採択したうえで食い違いを根拠欄に書く。どちらか一方を黙って選ばない。
- 発見が0件の賢者も行を残し、理由を備考に書く。
