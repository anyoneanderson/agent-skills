# 要求境界チェック

`requirement.md`が対象範囲を閉じ、すべての要求に観測可能な完了条件を定めているか検査する。

## 必須セクション

概要、機能要件、非機能要件、制約事項、前提条件、非目標の見出しを必須とする。
非目標の日本語別名として「対象外」を許可し、`## 6.`のような番号は見出し名の照合から除く。

## 非目標の検査

1. レベル2の「非目標」または「対象外」セクションを探す。
2. その見出しから次のレベル2見出しまたはファイル末尾までを読む。
3. 除外する機能、状況、責務を具体的に示す空でないリスト項目を1件以上要求する。
4. コメント、見出し、`なし`、`未定`、`N/A`などのプレースホルダーだけのセクションは空と判定する。

セクションの欠落または空欄をWARNINGとして報告する。ファイル、存在する場合は見出し行、具体的な除外項目を追加する提案を含める。

## 受入条件の検査

1. レベル2の機能要件と非機能要件のセクション内だけで、IDが`REQ-\d+`または`NFR-\d+`に
   一致する定義をすべて探す。
   `### [REQ-001] 要求名`と、旧形式の行頭`[REQ-001] 要求名`を許可し、対象セクション外の
   IDへの言及は定義として扱わない。
2. その定義から次の要求定義またはレベル2見出しまでを要求ブロックとして扱う。
3. ブロック内に`受入条件：`または`受入条件:`のラベルを要求し、Markdownの強調記号で
   囲まれたラベルも許可する。
   コロンの後ろに空でない条件を1件書く形式、またはラベルの下に空でないリスト項目を
   1件以上置く形式を許可する。
4. 未チェック・チェック済みのタスク記号はリスト項目として扱うが、`未定`、`N/A`、省略記号だけの項目は空と判定する。
5. 条件には観測可能な結果または閾値が必要で、要求名の言い換えだけでは合格にしない。

有効な受入条件一覧がない要求ブロックごとにWARNINGを1件報告する。要求ID、定義行、観測可能な合否条件を追加する提案を含める。

## findingのタイトル

- セクション欠落：`必須セクション「非目標」がありません`
- セクション空欄：`非目標に具体的な項目がありません`
- 受入条件欠落：`要求 {requirement_id} に受入条件がありません`
